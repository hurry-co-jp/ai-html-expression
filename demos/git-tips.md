# Git よく使う操作・逆引きメモ

日常の開発作業で頻出する具体的なシチュエーション別の操作手順です。

---

## 1. add したファイルを取り消したい（ステージング解除）

「うっかり余計なファイルを `git add` してしまったが、作業ツリーの編集内容はそのまま残したい」場合の手順です。

```bash
# 特定のファイルのみステージングを解除
git restore --staged <ファイルパス>

# ディレクトリ配下のファイルを一括でステージング解除
git restore --staged <ディレクトリパス>/

# add したすべてのファイルを一括でステージング解除
git restore --staged .
```

> [!NOTE]
> ファイルの編集内容そのものを破棄して直前コミットの状態に戻したい場合は、`--staged` を付けずに `git restore <ファイルパス>` を実行します。

---

## 2. 直前のコミットから特定のファイルだけ取り消したい

「直前のコミットに含めるつもりのなかったファイルを誤ってコミットしてしまった」場合の安全な修正手順です。

### 手順 A: 直前のコミットから対象ファイルだけを除外して上書き（推奨）

作業ツリーの変更は残したまま、コミットからのみ特定ファイルを取り除きます。

```bash
# 1. 直前のコミット（HEAD~1）の状態から対象ファイルをステージング領域に上書き
git restore --staged --source=HEAD~1 <除外したいファイルパス>

# 2. 直前のコミットをメッセージ変更なしで上書き
git commit --amend --no-edit
```
※ これにより、対象ファイルは「未ステージの編集状態」として作業ツリーに残り、直前のコミットからはきれいに除外されます。

### 手順 B: いったん直前のコミットをほどいてやり直す

```bash
# 1. 直前のコミットのみを取り消す（変更内容はすべてステージング状態に残る）
git reset --soft HEAD~1

# 2. 除外したいファイルだけステージングを解除
git restore --staged <除外したいファイルパス>

# 3. 残りのファイルで改めてコミット
git commit -m "コミットメッセージ"
```

## 3. 最新のリモートを Pull する前にコミットして Push したときのやり方

リモートリポジトリ（GitHub 等）側に自分以外の新しいコミットがある状態で、ローカルでコミットを作成してそのまま `git push` するとエラー（`[rejected - non-fast-forward]`）になります。

この場合、リモートの最新履歴を取り込んでから Push します。

### パターン 1: コンフリクトがない場合

履歴を一本のきれいな直線に保つため、リベース形式で取り込むのが標準的です。

```bash
# 1. リモートの最新変更を自分のコミットの後ろに付け替える（リベース）
git pull --rebase origin <ブランチ名>

# 2. 取り込み完了後、そのままリモートへ送信
git push origin <ブランチ名>
```

### パターン 2: コンフリクト（競合）が発生した場合

リモートの変更と自分のコミットで同一箇所が変更されていた場合、リベース処理が一時停止します。

```bash
# 1. pull --rebase を実行
git pull --rebase origin <ブランチ名>
# （CONFLICT が発生し、リベースが途中で止まる）

# 2. 競合しているファイルを確認
git status

# 3. 対象ファイルを開き、競合マーカー（<<<<<<< / ======= / >>>>>>>）を手動で編集して解消

# 4. 解消したファイルをステージング
git add <解消したファイルパス>

# 5. リベース処理を再開（コミットは作成しない）
git rebase --continue
# ※ 他のコミットでも競合が出た場合は 3〜5 を再度繰り返します

# 6. リベースが正常に完了したらリモートへ送信
git push origin <ブランチ名>
```

> [!TIP]
> 途中で混乱してしまい、いったん最初の状態（リベース前）に戻したい場合は以下のコマンドで完全に中止できます。
> ```bash
> git rebase --abort
> ```

## 4. 特定のファイルのみの変更履歴を見たい

プロジェクト全体のログではなく、特定ファイルがどのように変更されてきたかを調査するコマンドです。

```bash
# 特定ファイルのコミット履歴を 1 行ずつコンパクトに表示
git log --oneline <ファイルパス>

# コミット履歴に加え、それぞれの変更差分（diff）も同時に表示
git log -p <ファイルパス>

# ファイル名が変更された過去の履歴も含めて追跡して表示
git log --follow --oneline <ファイルパス>
```

---

## 5. 特定のファイルのみ、特定のブランチとの差分を見たい

「現在作業中のブランチと main ブランチの間で、このファイルだけ何が違うのか」を確認する手順です。

```bash
# 現在のブランチと指定ブランチの間で特定ファイルの差分を表示
git diff <比較対象ブランチ> -- <ファイルパス>

# 例: main ブランチと現在のファイルの差分を見る
git diff main -- app/contents/memo/git-tips.md

# 2 つのブランチ同士を指定して特定ファイルの差分を見る
git diff <ブランチA> <ブランチB> -- <ファイルパス>

# 差分の詳細ではなく、変更された行数・規模だけをサッと確認したい場合
git diff <比較対象ブランチ> --stat -- <ファイルパス>
```

## 6. ローカルで Push 前にコミットしたものを 1 つにまとめたい

作業途中で細かく「WIP」「修正」などとローカルコミットを重ねた後、リモートへ Push する前にきれいな 1 つのコミットにまとめる手順です。

### 方法 A: リモート Push 済み地点まで一括でまとめる（件数のカウント不要・推奨）

「何件コミットしたか」を数える必要がなく、前回の Push 地点からローカルで新しく積んだコミットをすべて 1 発でまとめられます。

```bash
# 1. 最後に同期したリモート地点（@{u}）まで一括巻き戻し
git reset --soft @{u}

# 2. 改めて 1 つの完成形コミットを作成
git commit -m "feat: ○○機能を実装"
```

> [!TIP]
> - **`@{u}`** とは、現在作業中のブランチが追跡しているリモートブランチ（例: `origin/feature-xxx`）を指す Git の標準シンタックスです。何件コミットがあっても自動で差分を認識します。
> - feature ブランチで作業しており「main から分岐してからの作業コミットを全部 1 つにまとめたい」場合は、**`git reset --soft origin/main`** を指定すると同様にカウント不要でまとめられます。

---

### 方法 B: 件数を指定して手動で巻き戻す

特定の件数（例: 直近 3 件分）だけをピンポイントでまとめたい場合に使用します。

```bash
# 1. 直近 3 件のコミットを取り消す（変更内容はすべてステージング状態に残る）
git reset --soft HEAD~3

# 2. まとめたコミットを作成
git commit -m "feat: ○○機能を実装"
```

---

### 方法 C: インタラクティブ・リベースで統合する

過去のコミットメッセージを確認しながら選んでまとめたい場合です。これも `@\{u\}` や `origin/main` を指定すれば件数の計算は不要です。

```bash
# リモート未送信のコミット一覧をリベース画面で開く（件数カウント不要）
git rebase -i @{u}

# または件数を指定して開く場合:
# git rebase -i HEAD~3
```

エディタが開くので、2 行目以降の `pick` を `squash`（または短縮形の `s`）に変更して保存・終了します。

```text
pick 1a2b3c4 最初のコミット
squash 5d6e7f8 細かい修正 1
squash 9g0h1i2 細かい修正 2
```

その後、コミットメッセージの結合・編集画面が開くので、最終的に残したいメッセージに整えて保存します。

## 7. コミットメッセージを修正したい

### 直前のコミットメッセージを修正する場合
まだリモートへ Push していない直前のコミットメッセージを変更します。

```bash
# コマンドラインから直接新しいメッセージに上書き
git commit --amend -m "正しいコミットメッセージ"

# エディタを起動して複数行メッセージを編集
git commit --amend
```

### 過去の（数個前の）コミットメッセージを修正する場合
直前より前のコミットメッセージを直したい場合は、インタラクティブ・リベースを使用します。

```bash
# 修正したいコミットが含まれる範囲（例: 過去 3 件）を指定
git rebase -i HEAD~3
```

エディタが開いたら、修正したいコミットの行頭にある `pick` を `reword`（または `r`）に書き換えて保存します。

```text
pick 1a2b3c4 直前のコミット
reword 5d6e7f8 メッセージを直したい過去のコミット
pick 9g0h1i2 さらに前のコミット
```

保存して閉じると、対象コミットのメッセージ編集画面が立ち上がるので、新しいメッセージに書き直して保存します。
