コスト増減チェック自動化 検討資料

作成日: 2026-09-17

1. 協議事項（チーム合意が必要な論点）

※事前に方針を決定したい項目
No. 検討項目 背景・課題 主な論点 / 検討ポイント
01 HTMLの配置場所とアクセス制御 コスト情報は社外秘のため、一般公開は避ける必要がある。
手軽さと安全性のバランスをどう取るか：
  • • S3静的ホスティング：手軽だがIP制限等の設定が必要
  • • 社内サーバー / ポータル：アクセス管理は楽だが配置手順が必要
  • • 各自のローカル環境：最も安全だが手元での起動が必要
02 S3データの取得方式とセキュリティ ブラウザからS3の非公開データを直接取得しようとするとCORSや認証が課題になる。
メンバーの利用手順と安全性をどう両立するか：
  • • バケットポリシーでIP制限：ブラウザから直接取得（CORS設定が必要）
  • • 署名付きURLの発行：Lambda等で一時的なアクセス権を付与
  • • AWS CLI経由での取得：各自の認証情報を利用して手元に同期

2. 業務プロセスの変化（現状の手動作業 vs 自動化後のフロー）

プロセス 現状（課題・面倒な点） 自動化後（改善構想）
① データ取得 気付いた担当者が都度コンソールを開いて確認（チェックが属人化・形骸化しやすい） EventBridge により毎朝 08:00 に Cost Explorer API から日次コストを完全自動取得
② 差分計算 日付フィルターを変更してCSVダウンロードし、手作業で引き算・比較集計 Lambda が前日比・前週同曜日比を自動計算し、S3 に JSON として蓄積
③ 確認・共有 定着せず、月末に想定外の請求が届いて初めて消し忘れに気付くことがある 専用HTML画面を開くだけで、増減（前日差分・前週差分）が一目で確認可能

3. 期待される効果

✓
早期検知によるコストロス削減
毎朝の確認がサッと終わるため、検証用インスタンスの消し忘れや想定外の負荷急増に当日中に気付ける。
✓
判断速度の向上
汎用画面ではなく「自分たちが見たいサービス別の差分」だけに特化しているため、迷わず状況を把握できる。
