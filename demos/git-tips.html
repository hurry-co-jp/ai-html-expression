Git よく使う操作 Canvas 図解リファレンス

日常の開発で頻出する操作手順を、状態の推移（1. 発生時 → 2. コマンド実行 → 3. 完了後）が一目でわかる 3 ステップ横並び図解で整理しました。

作業ツリー（未ステージ）
ステージング領域
ローカルコミット
リモートリポジトリ（@{u}）
01

add したファイルを取り消したい（ステージング解除）

うっかり余計なファイルをステージングしてしまった際に、作業ツリーの編集内容は残したままステージング領域からのみ外します。

1 誤って add 済み
ファイルが誤ってステージング領域に登録されている状態です。
2 restore --staged 実行
git restore --staged を実行。ステージングからファイルが作業ツリーへ押し戻されます。
3 ステージング解除完了
ステージング領域が空になり、作業ツリーの編集内容は安全に保持されています。
# 特定ファイルのみステージングを解除（作業ツリーの編集内容は保持）
git restore --staged <ファイルパス>

# すべてのファイルを一括でステージング解除
git restore --staged .
02

直前のコミットから特定のファイルだけ取り消したい

直前のコミットに対象外のファイルを含めてしまった場合、そのファイルを作業ツリーへ戻しつつ、コミットを上書き修正します。

1 不要ファイルが混入
直前コミットに対象外ファイル（file-b）が誤って一緒にコミットされた状態です。
2 過去コミットから展開
1 つ前の親コミットから file-b の状態をステージング領域へ上書き展開します。
3 amend で除外して完成
git commit --amend により、file-a のみの新しいコミットへ差し替え完了しました。
# 1. 1 つ前のコミット（HEAD~1）の状態をステージング領域へ上書き
git restore --staged --source=HEAD~1 <除外したいファイルパス>

# 2. 直前のコミットをメッセージ変更なしで上書き
git commit --amend --no-edit
※ 対象ファイルは未ステージングの編集状態として作業ツリーに残るため、コードが消滅することはありません。
03

最新のリモートを Pull する前にコミットして Push したい時

リモートに新しいコミットが存在し Push が拒否された際、履歴を一本の直線に保つ `pull --rebase` で綺麗に統合して送信します。

1 ローカルとリモートの分岐
リモート側に別メンバーのコミット [R1] が追加されており、ローカル [L1] と分岐しています。
2 pull --rebase 実行
git pull --rebase を実行。ローカルコミット [L1] をリモート最新 [R1] の後ろへ付け替えます。
3 一直線になり Push 完了
履歴が一直線になり、競合なくスムーズに Push が完了します。
# 1. リモートの最新変更を自分のコミットの後ろに付け替える（リベース）
git pull --rebase origin <ブランチ名>

# 2. そのままリモートへ送信
git push origin <ブランチ名>

# ※ 競合が出た場合は修正して git add 後に git rebase --continue を実行
04

特定のファイルのみの変更履歴を見たい

プロジェクト全体のログではなく、該当ファイルがいつ・どのように変更されてきたかをピンポイントで調査します。

1 プロジェクト全体の履歴
全体コミットのうち、対象ファイルに関係するコミットと無関係なものが混在しています。
2 対象のコミットを抽出
git log <ファイルパス> により、該当ファイルに変更があったコミットのみを抽出します。
3 変更差分付きで確認
-p オプションにより、抽出したコミットごとの差分（追加・削除行）も同時に確認できます。
# 特定ファイルが関係するコミット履歴のみを 1 行ずつ表示
git log --oneline <ファイルパス>

# それぞれのコミットでの変更差分（diff）も同時に表示
git log -p <ファイルパス>

# リネーム前の過去履歴も追跡して表示
git log --follow --oneline <ファイルパス>
05

特定のファイルのみ、特定のブランチとの差分を見たい

現在作業中のブランチと main ブランチの間で、指定したファイルだけがどう変更されているかを比較します。

1 ブランチ間の差分指定
main ブランチと現在のブランチを指定し、特定ファイルのみを比較対象にします。
2 ファイルの中身を比較
2 つのブランチにおける該当ファイルの中身を行単位で比較照合します。
3 追加行・削除行の可視化
緑色（+ 追加行）と赤色（- 削除行）で変更箇所が明確に対比表示されます。
# 現在の作業ブランチと main ブランチ間で特定ファイルの差分を表示
git diff main -- <ファイルパス>

# 任意の 2 つのブランチ同士で特定ファイルの差分を表示
git diff feature-a feature-b -- <ファイルパス>
06

ローカルで Push 前にコミットしたものを 1 つにまとめたい

追跡リモート地点（`@{u}`）を指定することで、コミット件数を自分で数えることなく、前回の Push 地点以降の未送信コミットをすべて 1 発で統合できます。

1 Push 後に WIP が複数
前回の Push 地点（@{u}）から、ローカルに細かいコミットが積み上がっている状態です。
2 reset --soft @{u}
件数を数えることなく、@{u} までの未送信差分がステージング領域へ一括集約されます。
3 1 つの綺麗なコミットへ
改めてコミットを作成。Push 済み地点の直後に 1 本の綺麗なコミットとして完成します。
# 1. 最後に同期したリモート地点まで一括巻き戻し（何件あっても自動認識）
git reset --soft @{u}

# 2. 改めて 1 つのまとまったコミットを作成
git commit -m "feat: ○○機能を実装"

# ※ main から分岐した作業コミットをすべてまとめたい場合:
git reset --soft origin/main
※ `@{u}` は現在ブランチの追跡リモートブランチ（上流ブランチ）を表すため、件数を手作業で数える必要が一切ありません。
07

コミットメッセージを修正したい

タイポや記述漏れがあったコミットメッセージを、Push 前の段階で手軽に修正・上書きします。

1 メッセージに誤字がある状態
コミット「feat: ユーザ認証追加（タイポあり）」のメッセージに誤字がある状態です。
2 git commit --amend 実行
git commit --amend を実行し、既存のコミットのメタデータを上書き修正します。
3 メッセージ修正完了
正しいメッセージが反映された新しいコミットに差し替えが完了しました。
# 直前のコミットメッセージを新しいメッセージへ直接上書き
git commit --amend -m "正しいコミットメッセージ"

# エディタを起動して複数行メッセージを編集したい場合
git commit --amend
